# 画面・操作設計（veliora-sales）

Issue #17。Jevの実結果 `veliora-sales` を低信頼度0.21も含めてユーザーが採用承認した。選定と承認の原記録は [WORK/design-access.md](../WORK/design-access.md)、受理された入力・応答は [WORK/design-selection/](../WORK/design-selection/) を参照。

## 視覚参照と適用

https://sample.chartd.net/veliora-sales/ は親スレッドのクラウドブラウザーで確認済み。紺・オレンジの日本語B2B SaaSサイト、カード・KPI・FAQが出典。ヒーローのダッシュボードはモニター画像であり、このアプリのフォームや金融計算を提供する参照ではない。既存の認証付きアプリ操作に、以下の視覚仕様を適用する。

- 紺: `#0a1628` / `#0d1f3c` / `#122245`。操作のアクセントは `#f47c20`、ホバーは `#ff9340`。明るい領域は `#f5f7fa`。
- ボタン6px、カード12px、FAQ・小領域10pxの角丸。紺の濃淡・境界線・控えめな影で情報を分ける。
- 見出し・値は強いウェイト、本文は日本語を読みやすいサンセリフ。元指定はBarlow / Noto Sans JP。外部フォント通信を追加せず、利用可能なローカル書体とOSの日本語フォールバックを使う。
- 明るいオレンジに白文字を重ねず紺文字を使う。本文・補足・エラー・フォーカスのコントラストをブラウザーで検証する。
- 金融入力画面に宣伝用の架空KPI・過剰な装飾・背景画像を持ち込まない。カードの値は実際の計算結果のみ。

## 認証と画面構成

ログイン画面はGoogleログイン、本人限定のサーバー保存、仮定による計算という説明を表示する。認証前に財務入力を表示しない。

認証後はアカウント・ログアウト・保存状態を表示する。条件設定には共通条件、ケース切替、手取り・生活費・資産・率、投資配分、イベント、計算・保存を配置。PCでは設定と結果を比較しやすい配置、スマートフォンでは1列とする。

グラフ・結果の値と月次明細は同じ計算結果を使う。入力変更後は前回結果である旨を表示。不足月で線と明細を終える。最大3ケースは名前・線の表現でも区別し、色だけに依存しない。表は領域内で横スクロール可能にし、画面全体の横はみ出しを防ぐ。

保存・更新・読込・複製・削除、未保存消失・削除の確認ダイアログ、競合・失効・保存失敗への案内を維持する。削除操作は通常操作と見分けられ、キーボードで確認・取消できる。

## 検証と制約

架空データでPC・モバイル、キーボード、フォーカス、ラベル、エラー、比較、月次表、確認ダイアログを確認する。外部フォント・画像・AI・解析リクエストを追加しない。公開前のローカルプレビュー、未構成Google OAuth、未確定のバックアップ保持方針という既存の案内は維持する。デプロイは行わない。
